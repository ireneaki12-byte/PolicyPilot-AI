6.5	Handling Data Subject Requests
This document defines the actions for handling data subject requests at Kenya Aviation Limited.
5.5.1	Valid Data Subject Requests
1.	Data subject requests must meet the validity criteria set in the Kenya Aviation Limited Data Subject Request Policy section 4.2.
2.	Types of requests include access, rectification, restriction, erasure, and others as specified in the Data Protection Act.
3.	All valid requests are processed following the outlined procedures, ensuring compliance and accountability.

5.5.2	Requests for Access to Personal Data
Definition: A request by a data subject to view or understand how their personal data is processed.
Required Actions:
1)	Request Record: Log the request in the "Kenya Aviation Limited Data Subject Rights Request Form" (accessible at https://bit.ly/Kenya Aviation LimitedDataSubjectRightsRequestForm) if this is not already captured.
2)	Verify Request Validity: Confirm the request is valid, per Kenya Aviation Limited policy. Notify the requester promptly if it is invalid, providing reasons and guidance.
3)	Data Collection: Gather all relevant personal data across internal and external systems, including files, portals, and mailing systems.
4)	Third-Party Notification: Inform relevant departments or external processors of the request and request the data from them.
5)	Data Compilation: Consolidate all data into a structured format for delivery.
6)	Response to Data Subject: Send the requested data to the data subject upon DPO approval.
7)	Closure: Finalize the request and log it in the register compliance with the policy.

5.5.3	Requests for Rectification of Personal Data
Definition: A request by a data subject to correct inaccuracies or update their personal data.
Required Actions:
1)	Request Record: Log the request in the "Kenya Aviation Limited Data Subject Rights Request Form" (accessible at https://bit.ly/Kenya Aviation LimitedDataSubjectRightsRequestForm) if this is not already captured.
2)	Verification: Validate the request. Notify the requester if invalid, specifying reasons and next steps.
3)	Notification: Notify third parties who may have accessed the incorrect data.
4)	Rectify Data: Amend data across systems and replace outdated records.
5)	Mark Invalid Data: Tag outdated or incorrect data for clarity, including historical updates.
6)	Closure: Notify the DPO upon completion and close the request in the register.
5.5.4	Requests to Restrict Processing
Definition: A request to limit certain activities involving the processing of personal data.
Required Actions:
1)	Request Record: Log the request in the "Kenya Aviation Limited Data Subject Rights Request Form" (accessible at https://bit.ly/Kenya Aviation LimitedDataSubjectRightsRequestForm) if this is not already captured.
2)	Verification: Confirm the request is valid and permissible under applicable regulations.
3)	Inform Third Parties: Notify all relevant entities about the need to restrict processing activities.
4)	Restrict Data: Implement the requested restrictions across all systems.
5)	Closure: Inform the DPO of successful restrictions and close the request in the register.

5.5.5	Request for Erasure of Personal Data
Definition:
A data subject requests the deletion of their personal data under specific circumstances, such as when the data is no longer necessary for its intended purpose.
Required Actions:
1)	Request Record: Log the request in the "Kenya Aviation Limited Data Subject Rights Request Form" (accessible at https://bit.ly/Kenya Aviation LimitedDataSubjectRightsRequestForm) if this is not already captured.
2)	Verify Request Validity: 
a)	Confirm the request meets the criteria outlined in the Kenya Aviation Limited Data Subject Request Policy.
b)	Ensure there are no overriding legal or operational requirements to retain the data (e.g., legal retention periods).
3)	Data Erasure: 
a)	Delete all applicable personal data from internal systems, databases, and archives.
b)	Notify all relevant third parties to erase the data from their systems.
4)	Documentation: Record actions taken, including systems updated and third parties notified.
5)	Response to Data Subject: Inform the data subject of the erasure or provide reasons for partial/non-erasure if applicable.
6)	Closure: Close the request in the register after receiving confirmation from the DPO.

5.5.6	Request for Withdrawal of Consent
Definition:
A data subject withdraws previously given consent for the processing of their personal data.
Required Actions:
1)	Request Record: Log the request in the "Kenya Aviation Limited Data Subject Rights Request Form" (accessible at https://bit.ly/Kenya Aviation LimitedDataSubjectRightsRequestForm) if this is not already captured.
2)	Verify Request Validity: Confirm that the data subject's request aligns with their prior consent and is valid.
3)	Cease Processing: 
a)	Identify and stop all data processing activities based on the withdrawn consent.
b)	Notify relevant departments and third parties involved in the processing.
4)	Update Records: 
a)	Mark the data subject’s record to reflect the withdrawal of consent.
b)	Ensure no further processing activities are conducted without a valid legal basis.
5)	Response to Data Subject: Notify the data subject that their consent has been withdrawn and actions have been taken.
6)	Closure: Document and close the request in the register upon DPO confirmation.

5.5.7	Request for Data Portability
Definition:
A data subject requests the transfer of their personal data to another data controller in a structured, machine-readable format.
Required Actions:
1)	Request Record: Log the request in the "Kenya Aviation Limited Data Subject Rights Request Form" (accessible at https://bit.ly/Kenya Aviation LimitedDataSubjectRightsRequestForm) if this is not already captured.
2)	Verify Request Validity: Ensure the request meets the data portability criteria (e.g., data subject’s identity, format compatibility).
3)	Data Export: 
a)	Retrieve the requested personal data from all relevant systems.
b)	Ensure the data is compiled in a commonly used, machine-readable format.
4)	Transfer Data: 
a)	Securely transfer the data to the new data controller specified by the data subject.
b)	Confirm receipt of the data by the new data controller.
5)	Response to Data Subject: Inform the data subject once the transfer is complete, or provide reasons if it cannot be fulfilled.
6)	Closure: Record the transfer details, notify the DPO and close the request in the register.

5.5.8	Request to Object to Processing
Definition:
A data subject objects to the processing of their personal data, particularly for direct marketing or profiling purposes.
Required Actions:
1)	Request Record: Log the request in the "Kenya Aviation Limited Data Subject Rights Request Form" (accessible at https://bit.ly/Kenya Aviation LimitedDataSubjectRightsRequestForm) if this is not already captured.
2)	Verify Request Validity: Confirm that the objection meets the requirements outlined in the Kenya Aviation Limited Data Subject Request Policy.
3)	Cease Processing: 
a)	Halt all processing activities related to the data subject's objection.
b)	Notify relevant departments and third parties involved in the processing.
4)	Review Legitimacy: 
a)	Evaluate whether Kenya Aviation Limited has overriding legitimate grounds to continue processing.
b)	If no grounds exist, ensure processing remains halted.
5)	Response to Data Subject: Inform the data subject of the outcome of their objection, including actions taken or reasons for continued processing.
6)	Closure: Document the resolution and close the request in the register upon DPO confirmation.

•	All actions must adhere to the specified timelines as outlined in the Kenya Aviation Limited Data Subject Rights Request Policy.
•	The Data Protection Officer (DPO) is responsible for overseeing compliance and ensuring proper execution of all requests.
•	If a request is declined, the data subject must be notified promptly, with reasons provided and information about their right to escalate to the Office of the Data Protection Commissioner (Kenya).
